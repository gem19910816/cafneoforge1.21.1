## 二、移植做法

1. **反编译**：用 Vineflower 1.12.0 把 1.20.1 的 jar 反编译成 256 个 `.java` 文件。
2. **还原成员名**：1.20.1 Forge 的 `official` 命名空间是「Mojang 类名 + SRG 成员名」，反编译结果里全是
   `m_49966_`、`f_61362_` 这种名字。用 Forge `joined.tsrg` 与 MCPConfig 的 `srg_to_official_1.20.1.tsrg`
   建立 SRG → Mojang 映射表（64225 条），批量替换 5933 处引用，未映射 0 处。
3. **1.20.1 → 1.21.1 API 迁移**：见下表。
4. **资源迁移**：`assets/` 原样复制（人工校验与原 jar 逐文件一致），`data/` 按 1.21.1 规范改名并改格式。
5. **编译与验证**：ModDevGradle 2.0.148 + Gradle 9.5 + JDK 21 干净编译；
   用官方 NeoForge 21.1.255 开发环境专用服务器实测加载，客户端实测进入主菜单（见第五节）。

### 方块的 GeckoLib 部件

12 个方块使用 GeckoLib 动画方块模型（`BaseEntityBlock` + `GeoBlockEntity`），
另 3 个（`airdropsmall` / `lockedairdropsmall` / `lockedairdropsmallopen`）是普通方块。
所有 geo 模型、动画文件与贴图沿用原版。

### 代码改动清单

| 改动 | 影响面 | 说明 |
|---|---|---|
| SRG 成员名 → Mojang 名 | 5933 处 | `m_49959_`→`registerDefaultState` 等 |
| `DeferredRegister` / `RegistryObject` → `DeferredRegister.createXxx` / `DeferredHolder` | 全部 init 类 | NeoForge 1.21.1 注册体系 |
| 变量 capability → **Data Attachment** | `DyairdropModVariables` + 99 个 procedures | 1.20.1 的 `Capability` 在本版本推荐用 `AttachmentType`；`RegisterCapabilitiesEvent` 只保留物品栏能力 |
| 物品栏能力 → `RegisterCapabilitiesEvent` + `SidedInvWrapper` | 15 个方块实体 | 去掉 `getCapability` 覆写与 `LazyOptional` 字段，改由 `DyairdropModCapabilities` 统一注册 |
| 网络：`SimpleChannel` → `CustomPacketPayload` + `PayloadRegistrar` | 6 个包 | 按钮包 4 个、同步包 2 个；`PacketDistributor` 静态方法替代原 `PACKET_HANDLER` |
| 配置文件：`ForgeConfigSpec` → `ModConfigSpec`，`ModLoadingContext.registerConfig` → `ModContainer.registerConfig` | `AirdropconfigConfiguration`、`DyairdropModConfigs` | 配置项名称与分区（`worldevents` / `chestevents` / `Performance` / `FlaregunEvents` / `debug` / `mapcompat`）**与 1.20.1 版完全一致**，旧 `dyairdrop.toml` 可直接沿用 |
| 事件总线归位 | 5 个类 | 游戏事件（`PlayerLoggedInEvent` 等）注册到 `NeoForge.EVENT_BUS`；mod 事件留在 mod 总线 |
| 实体 API：`defineSynchedData(Builder)`、`getDefaultPickupItem`、`useWithoutItem`、`getDefaultPassengerAttachmentPoint`、`dropExperience(null)`、`hurtAndBreak(int, Level, LivingEntity, Consumer)`、`ContainerHelper.loadAllItems(..., Provider)` 等 | 7 个实体 + 15 个方块实体 | 1.21.1 签名调整 |
| `new ResourceLocation(a, b)` → `ResourceLocation.fromNamespaceAndPath` / `parse` | 40 个文件 | 构造器在本版本为 private |
| GeckoLib 3 → **GeckoLib 4** | 全部 geo 类 | 包名 `software.bernie.geckolib.core.*` → `software.bernie.geckolib.*`；`renderToBuffer`/`preRender`/`reRender` 颜色参数由 `float×4` 改为 `int color` |
| 数据包目录改名 | `loot_tables`→`loot_table`、`recipes`→`recipe`、`advancements`→`advancement`、`tags/blocks`→`tags/block` | 1.21.1 单数目录名 |
| 配方格式 | 5 个信号枪配方 | `result` 的 `"item"` → `"id"` |
| 掉落表格式 | 20 个（`dyairdrop` 前缀 15 + `zombiekit` 前缀 5 → 见下） | `loot_table` 类型条目字段 `"name"` → `"value"`；函数名补 `minecraft:` 前缀 |
| `pack_format` | `pack.mcmeta` | 15 → 34 |

### 已知的映射差异（非缺陷）

- **`zombiekit:chests/*` 掉落表 15 个**：原模组自带这 20 个掉落表，全部引用 `zombiekit`（末日生存工具包）
  的物品。该模组只有 1.20.1 Forge 版，1.21.1 无法安装，因此这 5 个（`largeairdrop1..5`）保留在
  `data/zombiekit/` 下、日志会提示 15 条解析失败（物品不存在）。**不影响启动，也不影响 `dyairdrop` 自身的
  空投功能**。`zombiekit` 已声明为**可选依赖**；装上 1.21.1 版后这 20 个掉落表即可全部生效。
- 原模组的 `grechest3.json` 引用 `item/gre`（原作本身就缺这张图，仅用于破坏粒子），保持原样未改。

## 三、构建方式

```bash
# 需要 JDK 21（本机为 Temurin / Microsoft OpenJDK 21）
./gradlew build          # 产物 → build/libs/dyairdrop-1.1.0.jar
./gradlew runServer      # 开发环境专用服务器
./gradlew runClient      # 开发环境客户端
```

构建参数：ModDevGradle `2.0.148`、NeoForge `21.1.255`、Parchment `2024.11.17`、
Gradle `9.5.0`、Java toolchain 21。

依赖：`libs/geckolib-neoforge-1.21.1-4.9.3.jar` 以 `flatDir` 方式引入（编译期 + 运行期）。

- **与整合包其他模组的兼容**：1.21.1 环境下仅与 GeckoLib 一并测试，未加入完整 CAF 整合包验证。

**首要风险项**

1. 玩法逻辑未实跑 —— 若出现空投不触发 / 面板打不开 / 模型不显示，需按 `latest.log` 定位。
2. `procedures` 中有 3 处基于 `Minecraft.getInstance()` 的客户端判断（`OpshowProcedure`、
   `FlareticksProcedure`、`Safeopen2Procedure`），迁移时保留了原写法。原版靠 `DistExecutor` 隔离，
   本版本改为 `entity.level().isClientSide()` 分支保护；**专用服务器实测未触发异常，但未在多人客户端覆盖全部分支**。
