# 末日装饰容器附属 — 实现与验证说明

> 本文件按仓库惯例（`移植说明.md` = 改动清单与验证结果）编写。
> **本模块不是移植**：它是给《末日装饰》新写的**附属模组**，原模组 jar 一个字节都没有改动。

---

## 1. 它做什么

把《末日装饰》里 **114 种"看起来像容器"的方块**变成真正的容器：

| 效果 | 说明 |
|---|---|
| 右键开界面 | 按方块大小自动 1~6 行（9 / 18 / 27 / 36 / 45 / 54 格），用原版箱子界面 |
| 开关音效 | 按类型分 **16 种**（见第 4 节），同一容器多人同开只响一次 |
| 内容持久化 | 存在方块实体的 `Items` 里，随存档保存，重启后原样还在 |
| 物品处理器能力 | 注册 `Capabilities.ItemHandler.BLOCK`，漏斗 / 溜槽 / 物流管道 / 其他模组可存取 |
| 比较器 | 按装满程度输出红石信号 |
| 破坏掉落 | 方块破坏时内容物完整掉落，不会吞物品 |
| 潜行右键 | 不拦截，保持方块原有的装饰交互 |
| 老存档 | 已经放下的装饰方块在第一次右键时自动补建方块实体，不用拆了重放 |

---

## 2. 为什么写成附属（Mixin），而不是改原模组源码

一个方块要成为真容器，有两个绕不过去的硬条件：**方块类实现 `EntityBlock`** + **注册 `BlockEntityType`**。
原模组 1143 个方块全是纯 `Block`，所以"动到方块类"无法避免；区别只在动在哪：

1. `末日装饰/src` 是 **CFR 反编译产物**（1.20.1 → 1.21.1 手工移植版），直接手改 114 个类，
   下次重新移植或重新生成时要再合并一遍。
2. Mixin 方案**不改原模组 jar**，原模组照常升级/替换。
3. 附属带**保险丝**：`DoomsdayContainersMixinPlugin` 在应用每个混入前确认目标类存在
   （覆盖式混入还会确认目标方法存在），原模组删掉或改名某个方块时只跳过那一个，其余照常，不会崩游戏。
4. 附属可以**独立编译、独立发版**：混入目标是以字符串形式写的类名，编译期不需要原模组 jar。

## 5. 顺手修掉的原模组两处问题

1. **板条箱界面是「空的 27 格箱子」**：`AcrateBlockEntity.createMenu` 用的是
   `ChestMenu.threeRows(id, inventory)` —— 既没有把自己的库存传进去（界面永远是空的），
   又用了 3 行（27 格）而它实际只有 9 格。
   已用 `AcrateBlockEntityMixin`（`@Overwrite`）改为 1 行 + 绑定自身库存。
2. **板条箱在生存模式下其实打不开界面**：1.21.1 的生存右键入口是 `useWithoutItem`
   （`useItemOn` 返回 `PASS_TO_DEFAULT_BLOCK_INTERACTION` 之后才会走到），
   而 `getMenuProvider` 在 `ServerPlayerGameMode` 里只出现在**旁观者**分支
   （`javap` 核对：`getMenuProvider` 在该类中仅 1 处引用）。
   原模组只实现了 `getMenuProvider`，所以生存右键没有任何反应。
   附属在 114 个方块上都注入了 `useWithoutItem`，板条箱的入口由 `AcrateBlockMixin` 补上，同时补了开关音效。

## 6. 实现要点（踩过的坑）

- **必须在 `RegisterEvent`（方块实体类型阶段）里读清单**：模组构造阶段所有注册表都是空的，查方块只会查到空气。
- **不能用 `instanceof EntityBlock` 判断"原模组是否自带方块实体"**：这个附属正是给所有目标补上了该接口。
  是否原生由生成清单时对源码的分析结果（JSON 里的 `native` 字段）决定（全模组只有 `acrate`）。
- **方块实体类型不能用传入的 `BlockState` 反查**：区块序列化重建方块实体时，若该位置已经是空气
  （破坏方块后残留的方块实体 NBT），传进来的 state 是空气，反查得到 `null`，会在 `BlockEntity` 构造里 NPE。
  现在类型由注册时用 holder 捕获，state 不可用时回退到方块默认状态（实测已无该报错）。
- **1.21.1 的 `ChestMenu(MenuType, int, Inventory, Container, int)` 是 public**，
  配合 `MenuType.GENERIC_9x1…9x6` 就能不写任何客户端代码，直接用原版 `ChestScreen` 渲染 1~6 行。
- **`SoundEvents.ARMOR_EQUIP_LEATHER` 在 1.21.1 是 `Holder<SoundEvent>`**，要 `.value()`（编译期才发现）。
- 混入类只合并"自己声明的方法"，所以逻辑统一放在 `ContainerHooks`，生成出来的每个混入类只做转发。

## 8. 未验证 / 风险

- **客户端图形界面与音效听感未实机目视 / 试听**：专用服务器只能验证菜单类型、行数、库存绑定与音效派发。
  附属用的是原版箱子菜单类型与原版 `ChestScreen`，预期一致，但请进游戏右键一次确认。
- **多人并发未实测**：多人同开只响一次的逻辑按原版箱子写法（`0→1` / `1→0` 计数），未做多人压测。
- **客户端必须也装本附属**：方块实体类型与界面是双端注册的。
- **移除附属后**：已放进容器里的物品会变成孤儿方块实体 NBT（和原版拆掉箱子一样），拿不出来；移除前请清空容器。
- **与原模组版本绑定的是方块类名**：原模组大改类名时对应混入会被跳过（日志打印「目标方块不存在，跳过混入」），
  该方块退回普通装饰，其余不受影响。

## 9. 构建

```bash
./gradlew build          # JDK 21 + Gradle 9.5.0（随附 wrapper）+ ModDevGradle 2.0.148 + NeoForge 21.1.255
# 产物 build/libs/doomsdaycontainers-1.0.0.jar
```

编译**不需要**原模组 jar（混入目标是字符串类名）。想在开发环境里连着原模组一起跑，
把原模组的 jar 放进 `libs/` 并取消 `build.gradle` 里那行 `runtimeOnly` 注释。
无网环境可用 `tools/build.ps1`（离线 javac + jar，复用本机已缓存的 NeoForge 依赖）。
