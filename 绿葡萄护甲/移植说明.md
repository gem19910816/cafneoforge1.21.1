# LesRaisins Armor — NeoForge 1.21.1 移植说明

## 项目来源
- 原仓库: https://github.com/LesRaisins-Studios/LesRaisinsArmor
- 原版本: Forge 1.20.1 (mod_version 0.1.4.4)
- 目标版本: NeoForge 1.21.1 (neoforge 21.1.255,geckolib-neoforge 4.9.3)

## 移植要点

### 1. 工程骨架
- 从 dyairdrop NeoForge 1.21.1 工程复制 `net.neoforged.moddev 2.0.148` 模板
- `META-INF/mods.toml` → `src/main/templates/META-INF/neoforge.mods.toml`
- `pack.mcmeta` pack_format 升到 34

### 2. 主要 API 替换
| Forge 1.20.1 | NeoForge 1.21.1 |
| --- | --- |
| `ForgeConfigSpec` | `ModConfigSpec` |
| `ModLoadingContext.registerConfig` | `ModContainer.registerConfig` (构造注入) |
| `ForgeRegistries.ITEMS/MOB_EFFECTS` | `BuiltInRegistries.ITEM/MOB_EFFECT` |
| `RegistryObject<T>` | `DeferredHolder<T, T>` |
| `DeferredRegister.create(ForgeRegistries.X, ...)` | `DeferredRegister.create(BuiltInRegistries.X, ...)` |
| `new ResourceLocation(...)` | `ResourceLocation.fromNamespaceAndPath(...)` / `tryBuild` |
| `SimpleChannel` / `NetworkRegistry` | `CustomPacketPayload` + `StreamCodec` + `RegisterPayloadHandlersEvent` |
| `PacketDistributor.PLAYER.with(...)` | `PacketDistributor.sendToPlayer(player, msg)` |
| `LivingDamageEvent` | `LivingIncomingDamageEvent` |
| `TickEvent.PlayerTickEvent` | `PlayerTickEvent.Post` |
| `IEventBus` 通过 `FMLJavaModLoadingContext` | 构造器注入 `IEventBus` |
| `MobEffectInstance::getEffect` 返回 MobEffect | 返回 `Holder<MobEffect>`(影响 `removeEffect`/`hasEffect` 用法) |
| `ArmorMaterial` 接口 | `ArmorMaterial` record + `Holder<ArmorMaterial>` 传递 |
| 属性 Multimap | `ItemAttributeModifiers` + `EquipmentSlotGroup` |
| `ArmorItem.Type` | 1.21 新增 `BODY`,需要跳过(只支持头/胸/腿/脚) |
| `appendHoverText(stack, level, list, flag)` | `appendHoverText(stack, TooltipContext, list, flag)` |
| `MobEffect.applyEffectTick` 返回 void | 返回 boolean |
| `isDurationEffectTick` | `shouldApplyEffectTickThisTick` |

### 3. ArmorMaterial 方案
1.21 把 `ArmorMaterial` 从接口改为 record,且 ArmorItem 构造时需要 `Holder<ArmorMaterial>`。
原模组用 `AbstractArmorMaterial` 包装并把属性委托给 `LrArmorItem`,在 1.21.1 里这种做法不可行
(`getDefaultAttributeModifiers` 由 NeoForge 走 `ItemStack.getComponents()`)。
因此改为:
- `LrArmorMaterial.HOLDER` 提供一个占位 `Holder<ArmorMaterial>`(防御 1/2/3/1、耐久系数 13/15/16/11)。
- 真正的防御/韧性/击退抗性 通过 `LrArmorItem#getDefaultAttributeModifiers` 返回
  `ItemAttributeModifiers`(由 `ArmorData` 数据包驱动)。
- 耐久通过重写 `getMaxDamage(ItemStack)` 读取数据包。
- 装备音效通过 `getEquipSound()` 返回 `Holder<SoundEvent>`。

### 4. EpicFight 兼容
原模组有 `EpicFightCompat` 监听 `PrepareModelEvent`。NeoForge 1.21.1 版本的
EpicFight (`epicfight-neoforge-21.x`) 包名/事件结构变化较大,本次移植**未**包含 EpicFight
兼容,如果后续需要可以单独加。

### 5. 数据驱动 / 网络同步
- 服务端 `ArmorDataManager` 仍然扫描 `data/lrarmor/armor_data/*.json`。
- 网络包改为 `ArmorDataMessage` record + `StreamCodec`,通过 `OnDatapackSyncEvent` 由
  `PacketDistributor.sendToPlayer` 同步给客户端。

### 6. 客户端隐藏部件
`RenderLivingEvent.Pre/Post` 在 NeoForge 仍有,逻辑保持不变。`ClientSetupHandler` 通过
`RegisterClientReloadListenersEvent` 注册 `ArmorRenderConfigManager`(资源重载监听)。

### 7. Mixin
`EffectInstanceMixin` 保留(把 `SuitEffect` 标记为无限持续,避免显示计时)。`compatibilityLevel`
升到 `JAVA_21`。

## 已知问题 / 后续工作
1. 需要 NeoForge 21.1.x + geckolib 4.9.3+ 才能运行。
2. `EpicFightCompat` 未迁移,如服务器需要可后续加。
3. `JEI` 兼容代码未迁移(原项目只在 build.gradle 引用,代码里其实没用)。
4. `pack.mcmeta` pack_format 用了 34(1.21.1 资源包标准)。
5. 客户端只在 `RenderLivingEvent` 中隐藏玩家模型部件;若 armor_display JSON 在数据包中被
   修改,客户端需要重启或重进世界才会重新加载(原有行为)。

## 本仓库相对交付包做的调整(重要)

1. **修正数据包目录名 `recipes/` → `recipe/`**。交付包里 62 个配方在 `data/lrarmor/recipes/`(复数)。
   1.21.1 的注册表键已经是单数(`Registries.RECIPE = createRegistryKey("recipe")`,数据目录由
   `Registries.elementsDirPath()` 推导),复数目录会被**静默忽略** —— 后果是 16 套护甲**一件都合不出来**。
   已把源码目录改名为 `recipe/`,并同步把 jar 内 63 个条目(1 个目录项 + 62 个配方)改名;
   **全部 332 个条目的内容逐个 SHA256 比对一致**,即除路径外 jar 内容与交付产物完全相同。
   (`armor_data/` 是模组自己扫描的自定义目录 —— `ArmorDataManager` 里 `listResources("armor_data", …)` ——
   不受本次改名影响。)
2. **不提交 `libs/` 与构建产物**。GeckoLib 4.9.3 请按 `README.md` 自备放进 `libs/`;
   `build/`、`.gradle/`、`build_log*.txt` 不入仓库。
3. **`gradle.properties` 去掉原作者机器专用配置**:删掉 `org.gradle.java.home` 与
   `org.gradle.java.installations.paths` 两行(指向 `C:\Users\79662\jdk21\…`),改由构建机自行提供 JDK 21。
