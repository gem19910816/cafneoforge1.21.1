# SelfAid 移植说明

## 这是什么

用户需求：「把 FirstAid（ichttt）迁移到 NeoForge 1.21.1，**要没有风险的、自制的**」→ 之后用户明确要求直接使用 FirstAid 的物品贴图。

因此本项目**不是**对 ichttt/FirstAid 源码的反编译或移植，而是按其玩法概念（分部位生命值 + 急救物品 + 死亡规则）**从零重写**的原创实现：

- 代码：全部原创，约 8 个 Java 类（`com.gem19910816.selfaid`），未参考/未复制 FirstAid 任何源码；
- 贴图：`bandage.png`、`plaster.png`、`morphine.png` 三张物品贴图**直接取自 FirstAid 原版素材**（用户要求）；FirstAid 是 **GPL-3.0** 开源，自用无任何问题，若日后公开发布需附 GPL-3.0 声明及出处（README 已标注）；急救包贴图为程序化原创像素画（`tools/gen_textures.py`）；
- 模组 ID / 命名：`selfaid`（"Self-made FirstAid"），与 `firstaid` 完全独立，**可与原版 FirstAid 共存吗？不能也不应该**——两者都会重分配玩家伤害，同时装会互相干扰，只装其一；
- 模型/配方/语言文件：全部为本模组自写。

## 功能清单（对照 FirstAid 概念）

| FirstAid 概念 | SelfAid 实现 |
|---|---|
| 六部位血量（头/躯干/双臂/双腿） | ✅ NeoForge 数据附加 `selfaid:body_health`，部位比例 20/30/10/10/15/15 |
| 弹射物爆头判定 | ✅ 按弹射物与玩家的相对高度判定头/躯干/四肢 |
| 摔落伤害集中腿部 | ✅ 摔落/钟乳石 75% 落腿、25% 落躯干 |
| 头/躯干/全身清空死亡 | ✅ 下一 tick 强制 `genericKill`，附自定义提示消息 |
| 急救物品持续回血 | ✅ 绷带/创可贴/吗啡/急救包 4 件，右键长按使用后按计划分时回血 |
| 吗啡清除负面效果 | ✅ 吗啡与急救包会清除负面状态 |
| 截肢惩罚（虚弱/缓慢） | ✅ 手臂空→虚弱，腿空→缓慢（双腿空→缓慢 III） |
| 自然回血分配 | ✅ 原版回血自动补到比例最低的部位 |
| 部位血量 HUD | ✅ 原版绘制 API 的六色块 HUD（绿→红），位置/缩放/开关可配置 |
| 医疗椅/复活系统 | ❌ 未实现（FirstAid 的进阶功能，超出自制范围） |

## 技术要点

- NeoForge `21.1.255` + ModDevGradle `2.0.148` + JDK 21，与合集仓库统一工具链一致。
- 数据存储：`AttachmentType<BodyHealth>`（Codec 序列化，随存档保存）。
- 网络同步：自制 S2C `body_sync` 包（6 个 float），登录/重生/换维度/数据变化时下发。
- 伤害分配：`LivingDamageEvent.Pre/Post`（用 Post 的最终伤害值，护甲/吸收已结算）；
  `genericKill`/虚空类伤害绕过分配，避免与强制死亡递归。
- 一致性对账：每 20 tick 把部位血量之和与玩家原生血量对齐（吸收其他模组造成的血量变动）。

## 尚未验证项与风险项

1. **未实机测试**：需要进入世界实际挨打/使用物品验证（重点：爆头判定、死亡触发、HUD 数值同步）。
2. 与其他改血量/伤害的模组（如更多血量类、护甲扩展类）叠加时，行为以「对账机制」兜底，但比例可能漂移。
3. 创造模式玩家与旁观者不参与分部位系统（设计如此）。
4. 自定义死亡消息只以聊天消息形式发给玩家本人，死亡界面仍显示原版「玩家死了」文案。
5. 吗啡配方消耗玻璃瓶（原版瓶装物品一般返还瓶子，本配方为一次消耗）。
