# 铳械弹药统一 (Ammo Unify) — 1.21.1 NeoForge 通用弹药模组

**注意：本条目不是「移植」。** 仓库里其它条目是把某个 1.20.1 的成品 jar 适配到 1.21.1；
本条目是**为了 1.21.1 从零实现的新模组**，功能对标 1.20.1 的
[Tacz-Unidict（TACZ：铳械协议）](https://github.com/Scarasol/Tacz-Unidict)——那个模组依赖的
TaCZ 1.1.7 弹药机制在 1.1.8 已被上游改掉，无法直接移植（见其 issue #5），所以改为新写。

源文件：**无**（非移植，无对应的 1.20.1 成品 jar）
对标实现：`[TACZ：铳械协议] TACZ Unidict-1.20.1-forge-1.5.0.jar`（仅供功能对照，未使用其中任何代码或素材）
产物：`ammo_unify-1.0.0.jar`（Minecraft 1.21.1 / NeoForge 21.1.255 / Java 21）
前置：**TaCZ 1.1.8 系列**（Modrinth 项目 `tacz-1.21.1`，`tacz >= 1.1.8`）

## 二、实现原理

TaCZ 1.1.8 里所有与弹药有关的逻辑最终都汇聚到同一个数据源 `CommonGunIndex.getGunData()`。
逐个核对过的链路：

| 功能 | TaCZ 内部实际路径 |
|---|---|
| 弹药匹不匹配 | `AmmoItemDataAccessor.isAmmoOfGun` → `gunIndex.getGunData().getAmmoId().equals(ammoId)` |
| 弹匣盒匹不匹配 | `AmmoBoxItemDataAccessor.isAmmoBoxOfGun` → 同上 |
| 换弹 / 退弹 / 背包扫弹 | `AbstractGunItem.canReload`、`findAndExtractInventoryAmmo`、`hasInventoryAmmo`、`dropAllAmmo` |
| 射击耗弹 | `ModernKineticGunScriptAPI.hasAmmoToConsume`、`consumeAmmoFromPlayer`、`reduceAmmoOnce` |
| HUD 备弹数 | `GunHudOverlay.handleInventoryAmmo` |
| 弹匣容量 | `putAmmoInMagazine` → `AttachmentDataUtils.getAmmoCountWithAttachment(itemStack, gunIndex.getGunData())` |
| 配件数值缓存 | `ChangeGunPropertyEvent` → `cacheProperty.eval(gunItem, gunIndex.getGunData())` |
| 真实弹道 | `shootOnce` 头两行 → `gunIndex.getGunData()` / `gunIndex.getBulletData()` |

因此本模组**只覆写 `CommonGunIndex` 的两个方法**，为需要统一的枪派生一份把 `ammoId`
换掉的 `GunData` 副本，其余字段原样保留。一处替换，上表八条同时生效。

几个实现要点：

- **不注入任何 lambda 或合成方法**（`lambda$xxx$N` 是编译器产物，上游一改就崩——
  这正是 Tacz-Unidict 在 1.1.8 上失效的原因）。本模组只依赖两个稳定的公开方法。
- TaCZ 的数据类（`GunData` / `BulletData` / `ExtraDamage`）只有 getter、无 setter 也无拷贝构造器，
  因此派生副本用**反射浅拷贝**（`Refl` 缓存全部 `Field`），嵌套对象共享引用。
- 派生结果按 `CommonGunIndex` **实例**缓存（`ConcurrentHashMap`，该类未重写 equals/hashCode，
  天然身份语义）；未命中时才走一次反射。
- `CommonGunIndex` 不记录自己的 gunId，`GunDataDeriver` 用
  `CommonAssetsManager.getInstance().getAllGuns()` 建一次反查表，枪包重载时清空。
- 派生过程中**反射直读** `CommonGunIndex.gunData` 私有字段，避免回调被改写过的 `getGunData()` 造成递归。

## 三、与 Tacz-Unidict 的功能对照（**刻意标清差异**）

| 能力 | Tacz-Unidict 1.5.0（1.20.1 Forge） | 本模组 1.0.0（1.21.1 NeoForge） |
|---|---|---|
| 按武器类别统一弹药 | 有（Toml 逗号串配置） | 有（JSON 规则表，`by_type` / `by_gun` / `ignore_guns`） |
| 弹药匹配 / 装填 / 退弹 / 背包 / HUD | 8 个 mixin 注入点 | 覆写 `CommonGunIndex` 2 个方法，自动全覆盖 |
| 弹匣容量 / 配件数值 | 5 个 mixin 注入点 | 同上，自动覆盖 |
| 每 (枪, 弹) 弹道覆写 | 有 | 有（19 个字段，未写的字段沿用原枪数值） |
| 任意物品当弹药（`$` 前缀） | 有 | **无**（刻意不做，见下） |
| 同一把枪多弹种轮盘切换 | 有 | **无** |
| 战利品表替换 | 有 | **无** |
| 移除带标签的配方 | 有 | **无** |
| 自定义投射物实体 | 有（含"打飞方块"） | **无** |
| 按实体类型 / 实体标签伤害修正 | 有 | **无** |
| mixin 注入点总数 | 约 14 个（含 5 个 lambda 注入） | **1 个类 / 2 个方法** |
| 上游 TaCZ 1.1.8 | 不兼容（崩溃） | 目标版本 |

**关于"任意物品当弹药"为什么不做**：TaCZ 的背包扫弹被
`checkAmmoStack.getItem() instanceof IAmmo` 卡死，要放开它就得在
`hasAmmoToConsume`、`handleInventoryAmmo`、`canReload`、`findAndExtractInventoryAmmo`、
`hasInventoryAmmo` 五处各注入一次（其中三处是 lambda）。用稳定性换这个功能不划算，
故本版不做，留作后续可选模块。

### 4.3 首要风险项：枪包布局

TaCZ 1.1.8 的枪包有两种装载方式，本模组采用**平铺内置式**
（`data/ammo_unify/index/ammo/*.json` 直接位于 jar 根），依据是 TaCZ 自身
`com.tacz.guns.api.resource.ResourceManager` 的注释：

> `@deprecated 不再使用旧的文件入口。现在你可以直接将 assets 和 data 内置在模组中，或者使用下面的新方法导出`

若该布局在实际版本上不生效（症状：创造模式物品栏里找不到那 6 种通用弹药），
`README.md` 第 7 节给出了切换为**导出式**布局的完整步骤
（移到 `assets/ammo_unify/custom/ammo_unify_core/` + 加 `gunpack.meta.json`
+ 调用 `ResourceManager.registerExportResource(...)`）。

## 五、已知限制

1. 统一之后，枪包原有的专属弹药对这些枪失效（这是"统一"的必然结果）。
   不想被统一的枪写进 `ignore_guns`。
2. 不支持同一把枪在多种弹药间切换。
3. `rules.json` 不做网络同步，客户端与服务端必须使用同一份配置。
4. 只对走 `ModernKineticGunScriptAPI` 的现代枪械生效；用 Lua 脚本自行处理弹药的枪包可能不受影响。
5. 需要 TaCZ **1.1.8 系列**；更早版本数据类布局不同，mixin 会在启动时明确报错而非静默失效。
6. **不要再同时安装 Tacz-Unidict**（二者做同一件事，会互相打架）。

## 六、构建方式

```bash
# 1) 准备编译用 TaCZ（本仓库不含它）
#    Modrinth 项目 tacz-1.21.1，下载 1.1.8-hotfix 系列主文件，放到 libs/
#    文件名需与 gradle.properties 的 tacz_jar 一致
# 2) 构建
./gradlew build        # Windows 用 gradlew.bat，产物在 build/libs/
```

- 本仓库已附带 Gradle wrapper（8.10.2），无需本机预装 Gradle，但需 **JDK 21** 并建议设置 `JAVA_HOME`。
- 与 `末日装饰` 那份不同，本次 ModDevGradle 的 Minecraft 反编译环节在本机**可以正常跑通**，
  因此这里给出的是标准 Gradle 构建，不是 javac 直编。
- 重新生成全部贴图 / 模型 / 数据 JSON：`python tools/generate_assets.py`
