## 二、这次移植实际修掉的问题

起始状态：`D:\PCL2\.minecraft\versions\齿腐新版本\mods\gore_edition-0.5.jar.disabled`
已是一份**源码层面**的 NeoForge 1.21.1 移植（含 GeckoLib 4.9 的 `core.*` → `animatable.*`/`animation.*`
整包改名、`SimpleChannel` → `CustomPacketPayload` + `PayloadRegistrar`、`RegistryObject` →
`DeferredHolder`、`ForgeConfigSpec` → `ModConfigSpec`、NBT → 数据组件等），但：

* 可反编译、**不可编译**；
* 专用服务器**启动即崩**；
* 数据包目录仍是 1.20.1 命名。

本次把它做成可编译、可启动、可通过验证的成品。

### 2.1 反编译产物的类型信息丢失（编译 0 错误）

用 Vineflower 1.10.1 反编译得到 915 个源文件后，javac 报 33 处错误，全部是反编译器丢失泛型/擦除造成的，
与移植逻辑无关，逐类修正：

| 修正 | 数量 | 说明 |
|---|---|---|
| `Builder.of(...)` 补显式类型见证 | 11 | 实体构造函数参数是 `EntityType<? extends X>`，推理退化成 `EntityType<Entity>`，改为 `Builder.<X>of(...)` |
| `new ArrayList(players())` 补元素类型 | 4 | 补成 `new ArrayList<Player>(...)` |
| `SavedData.Factory` 补类型实参 | 2 | `new Factory<MapVariables>(...)` |
| `MobEffectInstance` 构造反编译残留 | 1 | Vineflower `Unable to resugar constructor`，改写为等价语句 |
| 方块实体能力注册重写 | 3 | 见下 |

方块实体能力注册：原 1.20.1 代码在 `BlockEntity#getCapability` 里对 6 个方向各暴露一个
`SidedInvWrapper`（`null` 面不暴露）。反编译后变成 `new InvWrapper(be)`（整箱、忽略方向）。
已改回 `(be, side) -> side == null ? null : new SidedInvWrapper(be, side)`，与原行为一致。

### 2.2 `@EventBusSubscriber` 缺少 Dist 限定 → 服务器启动崩溃

```
java.lang.IllegalArgumentException: class ...HellAshesDimension$HellAshesSpecialEffectsHandler
  has no @SubscribeEvent methods, but register was called anyway.
```

NeoForge 的 `@EventBusSubscriber` 默认 `value = {CLIENT, DEDICATED_SERVER}`（见 FML 4.0.45
`AutomaticEventSubscriber`）。该类的处理器参数是**仅客户端存在**的
`RegisterDimensionSpecialEffectsEvent`，专用服务器上解析不到该类型，自动注册就失败。

全量扫描 915 个源文件后确认：其余 24 个客户端事件订阅类**都已**写成 `@EventBusSubscriber({Dist.CLIENT})`，
**只有这 1 个**漏了。已补 `value = Dist.CLIENT`。

> 1.20.1 上侥幸能跑，是因为 Forge 的 universal jar 在服务端也带客户端事件类；NeoForge 21.1 不再如此，
> 所以这是 1.21 必须补的一步。

### 2.3 `Tier#getIncorrectBlocksForDrops()` 返回 null → 数据包加载崩溃

```
java.lang.NullPointerException
  at net.minecraft.core.MappedRegistry.bindTags(MappedRegistry.java:412)
  at net.minecraft.server.ReloadableServerResources.updateRegistryTags
```

定位过程：逐个剔除模组标签目录后仍崩 → 说明不是标签数据；再把模组整体移除，服务器正常启动（`Done`），
确认是模组在**注册期**污染了注册表标签表。

根因：1.21 删除了 `Tier#getLevel()`，改由 `Tier#getIncorrectBlocksForDrops()` 承担。
移植时把原 `getLevel()`（三件工具都返回 **0**）直接映射成了 `return null`。而
`DiggerItem` / `AxeItem` 的构造函数会调用 `Tier#createToolProperties(...)`，
其中 `Tool.Rule.deniesDrops(this.getIncorrectBlocksForDrops())` 拿到 null 标签，
向方块注册表的标签表写入了 **null 键**，随后 `bindTags` 的
`Sets.difference(this.tags.keySet(), ...)` 对 null 键调用 `containsKey` 即抛 NPE。

修正（3 个 Tier 实现，`ExarrackSwordItem` / `ExecutionersAxItem` / `SwordOfAshesItem`）：

```java
public TagKey<Block> getIncorrectBlocksForDrops() {
   return BlockTags.INCORRECT_FOR_WOODEN_TOOL;   // 原 getLevel() == 0，等效木质工具
}
```

### 2.9 一进世界就断线（`Cannot encode empty ItemStack`）

**现象**：单人「一开就提示」——

```
连接已丢失
Internal Exception: java.nio.channels.ClosedChannelException
```

这只是症状。内置服务端在把玩家放进世界时抛异常，连接因此被关闭。真实堆栈：

```
java.lang.IllegalStateException: Cannot encode empty ItemStack
  at net.minecraft.world.item.ItemStack.save(ItemStack.java:400)
  at gore_edition@0.5 net.mcreator.gore.network.GoreEditionModVariables$PlayerVariables.writeNBT(GoreEditionModVariables.java:317)
  at gore_edition@0.5 ...GoreEditionModVariables$PlayerVariables.syncPlayerVariables(GoreEditionModVariables.java:276)
  at gore_edition@0.5 ...procedures.PlayerJoinWorldSetGenericProcedure.execute(PlayerJoinWorldSetGenericProcedure.java:33)
  at net.neoforged.neoforge.event.EventHooks.firePlayerLoggedIn(EventHooks.java:894)
  at net.minecraft.server.players.PlayerList.placeNewPlayer(PlayerList.java:272)
```

**原因**：1.21 的 `ItemStack#save` 对**空物品栈直接抛异常**（1.20.1 只是写一个空 tag）。
字段 `third_hand_itemstack_store` 的初值就是 `ItemStack.EMPTY`，
于是**任何玩家第一次进世界都必然崩在 `PlayerLoggedInEvent` 里**。
（1.20.1 原码第 328 行同样是无条件写入，所以在 1.20.1 上不会出问题。）

**修正**（写入端 + 读取端）：

* 写入端：栈为空时不写这个键；
* 读取端：键不存在时直接取 `ItemStack.EMPTY`，避免 `ItemStack.parse` 对空 tag
  刷 `Tried to load invalid item: 'No key id in MapLike[{}]'` 报错。

语义完全不变（**键缺失 ⇔ 空栈**），非空栈的往返序列化逐字段一致。

**回归验证**：另写了一个 `ge_regression` 探针模组，在 `ServerStartedEvent` 里直接调用出问题的那条调用链
（专用服务器无法真的登录一个玩家）：

```
[GE_REGRESSION] empty_stack_save_throws=true (IllegalStateException: Cannot encode empty ItemStack)
[GE_REGRESSION] WRITENBT_FRESH_OK keys=37 hasStoredStack=false
[GE_REGRESSION] ROUNDTRIP_NONEMPTY_OK item=minecraft:stone count=3
[GE_REGRESSION] ROUNDTRIP_EMPTY_OK
[GE_REGRESSION] DONE
```

第一行证明 1.21 确实会对空栈抛异常（即崩溃归因正确）；
第二行证明修复后全新 `PlayerVariables` 的 `writeNBT` 正常返回 37 个键、且不再写空栈键。
