# 全球市场 (Global Market) — 1.20.1 Forge → 1.21.1 NeoForge 移植报告

源文件：`https://github.com/gem19910816/CAF` 分支「齿轮与腐肉」→ `MOD/global-market`（1.20.1 Forge 47.4.10）
产物：`gearsandflesh_market-1.0.0.jar`（Minecraft 1.21.1 / NeoForge 21.1.255 / Java 21）

本次不只是移植：原版把市场数据存在**当前存档**里，本次把数据源整体改为**官网 API**，
因此除 API 版本适配外还有一整套新增功能（见第四章）。

---

## 一、移植结果一览

| 项目 | 数量 | 状态 |
|---|---|---|
| Java 类 | 32（原 20 + 新增 12） | 全部编译通过 |
| 网络数据包 | 11（原 9 + 新增 2） | 全部注册为 NeoForge Payload，StreamCodec 编解码 |
| 方块 | 1（市场终端 `market_terminal`） | 注册成功，无物品形态 |
| 物品 | 1（`caf:money` 货币） | 注册成功，带模型与贴图 |
| 配置项 | 4（API 地址 / 服务器标识 / 超时 / 终端限制） | 注册成功 |
| 资源文件 | 8（语言 2、货币模型贴图 2、终端 blockstate+模型 2、pack.mcmeta、neoforge.mods.toml） | 全部随 jar 打包 |

旧整合包脚本与其他模组对该模组的引用不受影响。

## 二、移植做法

1. **取源码**：从原仓库稀疏拉取 `MOD/global-market`（只取该目录，避免整仓 43 MB 与国内网络反复中断）。
2. **建工程**：NeoForge 1.21.1 + ModDevGradle 2.0.148 + Java 21，直接复用本机已有的
   NeoForge 21.1.255 与 Gradle 8.10.2 缓存，构建全程可离线。
3. **逐层迁移**：数据层 → 网络层 → 服务层 → 客户端界面，每层按 1.21.1 API 改写（清单见第三章）。
4. **改架构**：把 `MarketService` 的数据源从本地存档换成官网 API（`MarketApiClient`），
   并补齐绑定、创造检测、终端方块、钱包等新功能。
5. **编译验证**：`gradlew build` 干净通过，产出 `gearsandflesh_market-1.0.0.jar` + sources jar。
6. **运行期验证**：用 NeoForge 21.1.255 开发环境专用服务器实机加载，模组进入模组列表、
   货币注册成功、服务器正常启动到 `Done`。

## 三、代码改动清单（Forge 1.20.1 → NeoForge 1.21.1）

| 改动 | 范围 | 说明 |
|---|---|---|
| 网络层整体替换 | 11 个包 + `MarketNetwork` | `SimpleChannel` + `registerMessage` + `NetworkEvent.Context` → `CustomPacketPayload` + `PayloadRegistrar` + `IPayloadContext`；编解码统一改为 `StreamCodec<RegistryFriendlyByteBuf, T>`；协议版本号独立为 `"5"` |
| 发包 API | 全部发包处 | `CHANNEL.send(PacketDistributor.PLAYER.with(...))` → `PacketDistributor.sendToPlayer(player, payload)`；`CHANNEL.sendToServer(...)` → `PacketDistributor.sendToServer(payload)` |
| 物品序列化 | `MarketItemCodec` | `ItemStack#save(CompoundTag)` / `ItemStack.of(...)` → 网络用 `ItemStack.STREAM_CODEC`，跨存档/传官网用 `ItemStack.CODEC` + `RegistryOps`（JSON）；NBT 相关 API 全部改 `HolderLookup.Provider` |
| 物品比较 | 校验逻辑 | `ItemStack.isSameItemSameTags` → `ItemStack.isSameItemSameComponents` |
| 注册表 API | 全部 | `ForgeRegistries.ITEMS` → `BuiltInRegistries.ITEM`；`DeferredRegister.create(ForgeRegistries.X, id)` → `DeferredRegister.createItems/createBlocks` |
| `ResourceLocation` | 全部 | `new ResourceLocation(ns, path)` → `ResourceLocation.fromNamespaceAndPath(ns, path)`（1.21 起构造函数私有） |
| 存档数据 | `MarketWorldData` | 手工 `load/save` → `SavedData.Factory` + `DataFixTypes` + `computeIfAbsent`；`save` 增加 `HolderLookup.Provider` 参数 |
| 事件总线 | `MarketEvents`、客户端事件 | `@Mod.EventBusSubscriber(bus = FORGE/MOD)` → NeoForge `@EventBusSubscriber`；`TickEvent.ServerTickEvent` 的 `phase == END` → `PlayerTickEvent.Post`；`MinecraftForge.EVENT_BUS` → `NeoForge.EVENT_BUS` |
| 主类 | `GlobalMarketMod` | `@Mod` 无参构造 → 构造注入 `(IEventBus, ModContainer)`；配置改用 `ModContainer.registerConfig` |
| 客户端分发 | `MarketSnapshotS2C` 等 | `DistExecutor.unsafeRunWhenOn(Dist.CLIENT, ...)` → `FMLEnvironment.dist == Dist.CLIENT` 判断后再调客户端类 |
| 界面 API | `MarketScreen` | `stack.getTooltipLines(player, flag)` → `getTooltipLines(Item.TooltipContext.EMPTY, player, flag)`；`ForgeRegistries` → `BuiltInRegistries`；货币判断改为按注册物品比较 |
| 方块交互 | `MarketTerminalBlock` | `BlockBehaviour#use(...)` → 1.21.1 拆分为 `useItemOn` / `useWithoutItem`，本模组重写 `useWithoutItem` |
| 元数据 | 打包 | `META-INF/mods.toml` → `META-INF/neoforge.mods.toml`（`[[dependencies]]` 改为 `REQUIRED`/`versionRange` 新写法）；`pack.mcmeta` 资源包格式 48 |
| 构建 | 工程文件 | ForgeGradle 6 → ModDevGradle 2.0.148；Java 17 → Java 21 |

**没有改动**：模组命名空间与注册 ID、原有挂单/购买/取消/邮箱的交互语义、界面的视觉设计与配色、
手续费与限频的数值约定（这些数值现在由官网执行，MOD 内保留一份用于界面预览）。

## 四、新增功能（相对 1.20.1 版）

| 功能 | 实现位置 | 说明 |
|---|---|---|
| **官网 API 客户端** | `remote/MarketApiClient` | 基于 JDK `java.net.http.HttpClient` 的异步调用，HMAC-SHA256 签名、时间戳、nonce 防重放、超时与断网降级 |
| **账号绑定** | `MarketEvents` + `data/MarketWorldData` | `/market bind <绑定码>`、`/market unbind`；token 存于存档世界数据 |
| **存档创造检测（不可逆）** | `MarketEvents` + `MarketWorldData` | 监听游戏模式切换与每秒轮询，一旦进入创造/旁观即给该存档打永久标记，此后**禁止上传**（购买不受影响） |
| **市场终端方块** | `block/MarketTerminalBlock` | 不注册物品形态，创造物品栏与 `/give` 均无法获得，只能 `/setblock` 放置；右键打开市场 |
| **钱包（余额 ↔ 实体币）** | `DepositMoneyC2S` / `WithdrawMoneyC2S` + 界面钱包区 | 存入：背包实体币 → 官网余额；提取：余额 → 实体币经邮箱送达 |
| **内置货币 `caf:money`** | `GlobalMarketMod` | 1.21.1 整合包已无 KubeJS 注册的该物品，改由本模组注册（NBT 时代遗留的 ID 与官网协议保持一致） |
| **配置文件** | `config/MarketConfig` | `apiBaseUrl`、`serverId`、`requestTimeoutSeconds`、`requireTerminalBlock` |
| **界面状态适配** | `MarketScreen` | 未绑定时显示绑定指引；创造存档禁用上架并给出红字提示；审核中挂单显示「审核中」且不可买/不可撤 |
| **托管顺序保证** | `MarketService` | 先由官网托管物品、确认后才从背包扣除；若期间物品被移动，立即调官网取消接口退回，避免吞物品 |

## 五、验证状态与风险

**已验证**

- `gradlew build` 干净编译（0 error），产出 `gearsandflesh_market-1.0.0.jar`（约 128 KB）与 sources jar；
- NeoForge 21.1.255 开发环境专用服务器加载通过：模组出现在模组列表
  （`Gears and Flesh Global Market 1.0.0 (gearsandflesh_market)`），日志打印
  `Global Market currency is caf:money`，服务器正常启动到 `Done`。

**未验证（首要风险）**

1. **与官网 API 的实机联调**：绑定、挂单、购买、邮箱领取、钱包存取的全链路尚需真实服务端联调；
2. **多人并发**：同一挂单被两人同时购买、同一账号多端登录等竞态，依赖官网侧的数据库事务；
3. **界面视觉**：1435 行的市场界面按 1.21.1 API 迁移后未逐个页面做视觉核对；
4. **创造检测的绕过面**：玩家可用 NBT 编辑器直接改存档文件删掉标记，单机环境下无法彻底防御
   （这是刻意接受的设计：由官网侧的白名单/限价/审批兜底）。

## 六、官网 API 契约（本模组用到的接口）

所有请求：`POST/GET {apiBaseUrl}/api/v1/...`，JSON 信封 `{"ok":bool,"error":string|null,...}`。

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/bind` | 绑定码换 token（无签名，带 uuid/name/code/serverId） |
| GET | `/snapshot` | 市场快照：分页挂单、余额、邮箱计数、限频状态、分类计数、本人历史 |
| POST | `/listings` | 上架（`item` 为 ItemStack JSON、`price`、`worldClean`） |
| POST | `/listings/{id}/buy` | 购买 |
| POST | `/listings/{id}/cancel` | 取消 |
| POST | `/mailbox/claim` | 领取到期投递 |
| POST | `/mailbox/confirm` | 确认领取（`deliveryIds`） |
| POST | `/wallet/deposit` | 存入实体币（`amount`） |
| POST | `/wallet/withdraw` | 提取到邮箱（`amount`） |
| POST | `/admin/listings/{id}/{copy\|remove\|delete}` | 管理员操作 |

鉴权头：`X-GM-UUID`、`X-GM-Timestamp`、`X-GM-Nonce`、`X-GM-Sign`、`X-GM-Protocol`、`X-GM-Server-Id`。
签名串：`uuid \n nonce \n timestamp \n METHOD \n path \n sha256hex(rawBody)`，密钥为账号 token，算法 HMAC-SHA256。
