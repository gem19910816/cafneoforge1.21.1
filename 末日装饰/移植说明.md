## 二、移植做法

1. **反编译**：用 CFR 0.152 把 1.20.1 的 jar 反编译成 1154 个 `.java` 文件。
2. **还原成员名**：1.20.1 Forge 的 `official` 命名空间是「Mojang 类名 + SRG 成员名」，
   反编译结果里全是 `m_49966_`、`f_61362_` 这种名字。用 MCPConfig 的 `joined.tsrg`（混淆名 → SRG）
   和 Mojang 官方 1.20.1 映射（Mojang 名 → 混淆名）按「类 + 混淆名 + 描述符」三元组求交，
   得到该模组实际用到的 **153 个成员**（35 个字段 + 118 个方法）对应的 Mojang 名字，逐个核对无误。
3. **1.20.1 → 1.21.1 API 迁移**：见下表，全部为机械替换 + 4 个类的手工重写。
4. **资源迁移**：`assets/` 原样复制；`data/` 按 1.21.1 规范改名。
5. **编译与验证**：javac 21 干净编译（0 error），打包成 NeoForge 模组 jar，
   再用官方 NeoForge 21.1.255 专用服务器实机加载验证。

### 代码改动清单

| 改动 | 次数 | 说明 |

## 四、原模组自带的问题（**非本次移植引入**）

1. **`blood` / `blood_2` … `blood_6` 六个模型有无效贴图路径**
   模型里写着 `"missing": "doomsday_decoration:block/"`（路径为空）。经与 1.20.1 原 jar 逐字节比对，
   原模组就是这样，游戏会为这 6 个方块记录一条无效贴图警告。
   如需修复：把该值改成 `"doomsday_decoration:block/bloodstain1"` 即可。

2. **板条箱 `acrate` 的 GUI 打开的是空的 27 格箱子，而不是它自己的 9 格库存**
   `AcrateBlockEntity#createMenu` 返回 `ChestMenu.threeRows(id, inventory)`，这是原版「新建一个 27 格容器」的写法，
   并没有把方块实体自己的库存接上去。结果是：漏斗/管道放进箱子的物品在 GUI 里看不到（拆掉方块会正常掉落，不会丢）。
   原模组行为完全相同。如需修复：改成 `ChestMenu.threeRows(id, inventory, this)`。

以上两点都按「原封不动」原则**保持原样**，需要的话可以改。

## 五、构建方式说明

本机 Gradle + ModDevGradle 的 Minecraft 反编译环节（NeoForm 的 JST 步骤）在沙箱环境下报
`error while writing net.minecraft.world.ticks.package-info` 而中断（属于工具链在该环境下的问题，与本模组代码无关）。
因此最终 jar 采用**直接 javac 编译**得到：classpath = NeoForge 21.1.255 官方补丁类 + universal jar +
NFRT 已生成的 Mojang 命名 Minecraft jar + FML/Mixin/游戏库，编译结果与 ModDevGradle 应为等价产物。

- 可直接使用的成品：`doomsday_decoration-1.1.3-neoforge-1.21.1.jar`
- 完整可再编译源码：`doomsday_decoration-1.21.1-src.zip`（Gradle 工程结构，含 `build.gradle`）
- 构建/验证脚本：`tools/`（`port.py` 迁移脚本、`build_manual.py` 编译、`validate_resources.py` 资源校验等）
